# Проверки при загрузке и «Тесты» в report — техническая часть

Человеческая часть — см. [04-Чел-261002-webapp-proverki-zagruzki-i-testy.md](04-Чел-261002-webapp-proverki-zagruzki-i-testy.md).

## Архитектура

Четыре независимых блока, у каждого свой DoD и своя ветка.

- **A. Проверки при загрузке + журнал.** Python-модуль `src/upload_checks/`, не Metabase. Два этапа: `pre_ingest` (до записи, жёсткие ошибки) и `post_ingest` (после записи, сверки). Результат пишется в таблицу `upload_checks` в БД проекта.
- **B. «Дашборд» с «Тестами».** Клиент Metabase API читает подколлекцию «Тесты/<slug проекта>», запускает карточки-проверки, кэширует ответ. Карточка возвращает несошедшиеся строки: пусто = зелёный. Формулы проверок живут только в карточках (источник истины — Metabase и VIEW, см. «Семантический слой» в `architecture-standarts.md`), в код вебаппа SQL не копируется.
- **C. Редизайн страниц.** «Загрузка» (переключатели Проект/Кабинет, двери), «Проекты» (строки с дверями), «Профиль», шапка, общий компонент выпадающего списка.
- **D. Раздельные доступы ClickHouse.** Пользователи `app_cloudsix`, `app_realt`, `app_control` (права только на свою БД, на запись и чтение), отдельные read-only пользователи для Metabase на каждый проект. Вебапп выбирает учётные данные по проекту запроса. Пароли — `.env` на проде.

### Правила дедупликации (блок A) — зафиксировано владельцем

Дубли **не ошибка**. Недельная сводная и перекрывающиеся выгрузки заведомо содержат уже загруженные строки.
- При загрузке из файла отбрасываются строки, которые уже есть в таблице; пишутся только новые.
- Сравнение по **содержимому**, а не по имени файла: для Ozon текущий ключ `(cabinet, source_file, row_num)` включает имя файла и дубли под другим именем не ловит. Определить бизнес-ключ или хеш значимых колонок (исключая `source_file`, `row_num`, `loaded_at`).
- Сравнение **мультимножеством**: если в файле две одинаковые законные строки, а в базе одна, пишется одна. Дубли внутри самого файла не удалять, если в базе их нет столько же.
- WB: одна и та же операция (`srid`) в соседних отчётах с разными `report_number` — норма, это не дубль.
- В результате загрузки и в `upload_checks` обязательны числа: `rows_in_file`, `rows_written`, `duplicates_skipped`. Дубли отображаются как информационное сообщение (не красный статус); если в файле 100% дублей — отдельная пометка «файл уже был загружен».
- Перед внедрением проверить на реальных файлах CloudSix, что ключ дедупа даёт 0 ложных срабатываний.

Жёсткие проверки `pre_ingest` (ошибка = ничего не пишется): тип/расширение, файл читается, не пуст, все обязательные денежные колонки распознаны (список из `column_mapping_*.yaml`), номер отчёта парсится из имени (WB), кабинет принадлежит проекту.

### Экстра-столбцы (блок B)

Колонки, не попавшие в маппинг, уже пишутся в `wb_unmapped_columns_log` / `ozon_unmapped_columns_log` (имя, файл, время) а значения — в `extra_columns` строк данных. Карточка в «Тесты/<проект>» показывает: имя колонки, число файлов, последняя встреча, сумма числовых значений из `extra_columns` (чтобы видеть, не деньги ли это). Состояние «красный» — если колонка числовая и ненулевая и не внесена в маппинг; иначе «жёлтый». Первый кандидат — «Удержание Агентского НДС» (26 файлов CloudSix).

### Порядок работы внутри блока B

Первым шагом проверить права Metabase: может ли ключ с правом «просмотр» только на коллекцию «Тесты» запускать сохранённые native-карточки без права на native-запросы к БД. Если нет, ключ окажется шире задуманного — зафиксировать фактические права и решить вместе с владельцем, прежде чем писать остальное.

## Ограничения

- Стек: Flask, ClickHouse, Metabase v0.63; без новых тяжёлых зависимостей.
- Первый выпуск — CloudSix (WB, Ozon). Реальт и Боттлинг — следующим выпуском, код без жёсткой привязки к CloudSix.
- Деплой: `/var/www/report.finance-black.ru` — rsync-таргет без git, расходится с master; перед деплоем и после проверять актуальность нужных файлов явно.
- Доступ к прод-VPS по SSH (root) — только по явному разрешению владельца на конкретный шаг.
- Блок D честно ограничен: ключи хранит сервер вебаппа, при компрометации самого сервера они лежат рядом. Защищает от ошибки или инъекции в запросах одного проекта и от утечки одного ключа. Вынос в секрет-хранилище — отдельная будущая задача.

### Что НЕ делать

- Не использовать ключ `CC-ilyas` в вебаппе — только отдельный ключ отчётов.
- Не копировать SQL проверок в код вебаппа.
- Не блокировать загрузку из-за дублей и не молчать о них: пропускать и считать.
- Не писать в ClickHouse до прохождения всех жёстких проверок.
- Не показывать результаты чужого проекта и сырой текст исключений (в интерфейс — понятное сообщение, трейс — в лог без секретов).
- Не создавать кабинеты через форму загрузки и не принимать кабинет текстом.
- Не показывать зелёный статус, когда проверка не выполнилась или проверок нет.
- Не менять формулы метрик, Модель 49 и cron загрузки CloudSix в рамках этого ТЗ.
- Не удалять данные в проде при внедрении дедупа (дедуп только на входе новых файлов).
- Не отзывать широкого пользователя ClickHouse, пока Metabase, cron и вебапп не переведены на новых.

## Надёжность и проверки

- Metabase недоступен: «проверки временно недоступны» + время последнего успешного обновления.
- Нет подколлекции «Тесты/<проект>» или она пуста: «проверок для проекта нет».
- Карточка упала: красный статус «проверка не выполнилась».
- Битый/пустой/чужой xlsx: понятная ошибка, в базу ничего не записано.
- Сбой ClickHouse при записи: ошибка пользователю, повторная загрузка безопасна благодаря дедупу.
- Нет доступа к проекту: 403.
- Наблюдаемость: красная плашка, строка в `upload_checks`, ERROR в логе сервиса без секретов и PII.
- Тесты: `pytest` на жёсткие проверки (переименованная колонка, пустой файл, чужой кабинет), на дедуп (полный дубль, частичное пересечение, одинаковые строки внутри файла, Ozon под другим именем файла), на клиент Metabase (недоступен, пустая коллекция, ошибка карточки), на классификацию Дверей, на выбор пользователя ClickHouse по проекту. После деплоя — ручной чек-лист на реальных файлах CloudSix.

## Definition of Done (техническое)

Общее (из `architecture-standarts.md`): нет секретов в коде, конфиги в `.env`, внешние вызовы с обработкой ошибок, логирование по уровням, тест или ручной чек-лист на каждый пункт.

- **A:** все жёсткие проверки покрыты тестами; повторная загрузка того же файла даёт `rows_written=0`, `duplicates_skipped=N`; Ozon-файл под другим именем не задваивает; журнал `upload_checks` заполняется; сверка со сводкой WB показывается в результате.
- **B:** отдельный ключ отчётов выдан и проверен (нельзя писать, нельзя читать вне «Тесты»); «Дашборд» показывает три состояния и три сценария отказа; папка «Тесты» создана в Metabase с подколлекцией CloudSix и перенесёнными проверками (например `wb_payout_vs_summary_check`).
- **C:** переключатели Проект/Кабинет на «Загрузке», двери разделены на стандартные/индивидуальные, «Проекты» строками, блок в «Профиле» и колокольчик убраны, выпадающий список общий и стилизован; работает на телефоне; CSS пересобран (Tailwind JIT, см. гочтю в вики).
- **D:** созданы пользователи ClickHouse с минимальными правами; вебапп работает под ними; попытка проекта A прочитать/записать БД проекта B под своим ключом отклоняется (проверено явным тестом); Metabase переведён на read-only пользователей; широкий `default` не используется вебаппом.

## Self-check перед сдачей

- [ ] Файл с переименованной денежной колонкой отклонён, в таблице 0 новых строк
- [ ] Повторная загрузка того же WB-файла: записано 0, дублей N
- [ ] Загрузка Ozon-файла под другим именем: записано 0, дублей N
- [ ] Частично пересекающийся файл: записаны только новые, дубли посчитаны
- [ ] Сводка WB после загрузки сходится/не сходится показано на экране
- [ ] Metabase выключен: «Дашборд» не зелёный
- [ ] Ключ отчётов не может писать и читать вне «Тесты»
- [ ] Пользователь A не видит результаты проекта B; ключ A не открывает БД B
- [ ] Тесты проходят, деплой проверен на проде
- [ ] Реальт и Боттлинг продолжают работать
