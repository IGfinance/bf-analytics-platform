# Проверки при загрузке и «Тесты» в report

Техническая часть — см. [04-Тех-261002-webapp-proverki-zagruzki-i-testy.md](04-Тех-261002-webapp-proverki-zagruzki-i-testy.md).
Открывать по ходу реализации, не обязательно читать сразу целиком.
Термины (Проект, Кабинет, Сверка, Дверь, Тесты и др.) — см. [глоссарий проекта](../../../docs/glossary.md).

## Задача

Нам нужно изменить **загрузку отчётов WB/Ozon и разделы «Загрузка», «Дашборд», «Проекты» вебаппа report.finance-black.ru**,
чтобы **любая ошибка в данных (при ручной загрузке, расхождение с API или со сводкой) была видна пользователю сразу, а не находилась руками постфактум**,
и чтобы **доступ к данным каждого проекта был изолирован отдельным ключом ClickHouse**.

Сейчас: файл WB/Ozon при ручной загрузке пишется в базу без единой проверки (переименованная
колонка молча даёт пустые суммы, кабинет вводится текстом, повторная загрузка того же периода
задваивает цифры), а страница «Дашборд» пуста и не показывает результаты сверок.

## Условия результата

- [ ] Файл WB/Ozon с нераспознанной денежной колонкой, пустой, битый или не того типа — отклоняется целиком с понятным сообщением, в базу ничего не пишется
- [ ] Кабинет на форме загрузки выбирается из списка кабинетов проекта; создать новый кабинет через форму нельзя
- [ ] **Дубли не блокируют загрузку**: уже существующие строки пропускаются, записываются только новые. В результате загрузки явно написано, сколько строк записано и сколько дублей пропущено (из скольких)
- [ ] После записи итог файла сверяется со сводкой WB (если она загружена), результат «сходится / не сходится» виден сразу
- [ ] Результат каждой загрузки (кто, когда, файл, что прошло, что упало, сколько дублей) сохраняется в журнал в базе проекта
- [ ] «Дашборд» показывает результаты проверок из папки «Тесты» в Metabase (по проекту, при необходимости по кабинету): зелёные, красные, «проверка не выполнилась»
- [ ] На «Дашборде» видны «экстра-столбцы»: колонки из загруженных файлов, которых нет в маппинге (имя, в скольких файлах встретилась, когда в последний раз, есть ли в них числа), чтобы новую колонку WB/Ozon не пропустить
- [ ] Если Metabase недоступен или папка пуста — «Дашборд» честно об этом говорит, а не показывает зелёное
- [ ] Для вебаппа выдан отдельный ключ Metabase: только чтение, только папка «Тесты»
- [ ] «Загрузка»: переключатель Проект и Кабинет (в стиле дашборда, с собственным оформлением выпадающего списка), блоки разделены на «Стандартные двери» и «Индивидуальные двери»
- [ ] «Проекты»: одна строка = один проект, справа стандартные двери, разделитель, затем индивидуальные двери
- [ ] В «Профиле» нет блока «Доступные проекты», в шапке нет колокольчика уведомлений
- [ ] Для каждого проекта отдельный пользователь ClickHouse: вебапп пишет и читает базу проекта только под его ключом; Metabase читает под отдельным read-only пользователем
- [ ] Первый выпуск — проект CloudSix (WB и Ozon); Реальт и Боттлинг не ломаются

## Каких систем может коснуться (ориентир, не обязательство)

- Вебапп (`webapp/app.py`, шаблоны, `webapp/static`)
- Модули загрузки `src/wb_core.py`, `src/ozon_core.py`, `src/wb_summary_core.py`, `src/reconcile_wb.py`
- ClickHouse: БД `cloudsix`, `realt`, `control`; новые пользователи и права
- Metabase: коллекция «Тесты», группа и API-ключ только на чтение
- Прод-VPS: деплой вебаппа, `.env` на проде

## Пользователь / выгодоприобретатель

Любой пользователь с доступом к проекту: загружает файл, сразу видит ошибки,
затем идёт в «Дашборд» и смотрит, бьётся ли загруженное с API и другими источниками.
Выгодоприобретатель — владелец платформы: ошибка видна пользователю раньше, чем попадёт в отчёты, и
не требует ручной проверки. Стало лучше, если расхождение или ошибка загрузки видны сразу и без запроса к владельцу.

## Исполнение

- Исполнитель: Claude, по блокам A–D в отдельных ветках (по одной на блок), слияние в master по приёмке каждого блока
- Дедлайн: без жёсткого дедлайна, по мере готовности блоков
- Как сдавать: ветка на блок + заполненный self-check; деплой на прод выполняет исполнитель с проверкой актуальности файлов на проде до и после
