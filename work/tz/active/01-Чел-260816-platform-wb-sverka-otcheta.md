# WB: кабинет выпадающим списком + сверка сводного отчёта с еженедельными

Первое ТЗ из серии по автоматизации сборки отчётов WB (сейчас всё считается
формулами в Excel). Термины «еженедельный отчёт» и «сводный отчёт» — см.
[глоссарий проекта](../../glossary.md), это не одно и то же.

Техническая часть (архитектура, схема БД, каркас кода) — отдельно, см.
[01-Тех-260816-platform-wb-sverka-otcheta.md](01-Тех-260816-platform-wb-sverka-otcheta.md).
Открывать по ходу реализации, не обязательно читать целиком сразу.

## Задача

Нам нужно изменить **загрузку отчётов WB** (добавить форму загрузки сводного
отчёта и выпадающий список кабинетов), чтобы вместо ручной сверки в Excel
**появилась автоматическая проверка сводного отчёта по данным еженедельных
отчётов**, с показом расхождений.

Сейчас Илья вручную сводит отчёты по кабинетам в Excel с тяжёлыми формулами.
Боли:
- Ручной труд, файл может грузиться десятками минут на слабых компьютерах
  из-за сложных формул.
- Нельзя быстро прогнать новую проверку сразу по всем проектам — проверки
  реализованы индивидуально по файлам, и часто внедряются не везде.
- Невозможно перепроверить большие объёмы данных вручную.

Если не делать — команда продолжит терять время и будет расти риск ошибок
в отчётности перед клиентами. Ничего не сломается, но и не станет быстрее.

## Условия результата

- [ ] На обеих формах загрузки кабинет выбирается из списка уже известных
      (но можно вписать новый)
- [ ] Есть форма загрузки сводного отчёта WB
- [ ] После загрузки сводного отчёта сверка с еженедельными отчётами
      запускается автоматически и её можно также запустить вручную
- [ ] Для каждого отчёта видно: сошлось / не сошлось (с числом расхождения) /
      каких-то данных не хватает
- [ ] Формулы сверки (какие данные еженедельных отчётов складываются в какую
      цифру сводного отчёта) согласованы с Ильёй и реально проверены на живых
      отчётах, а не придуманы предположительно
- [ ] Старая загрузка еженедельных отчётов как работала, так и работает —
      ничего не сломалось
- [ ] В Metabase есть дашборд с результатами сверки
- [ ] Пройден ручной чек-лист проверки (см. техническую часть)

## Каких систем может коснуться (ориентир, не обязательство)

Если найдёшь более удачный путь без изменения части из них — можно решить
иначе, но тогда явно опиши, что и почему сделано по-другому.

- **ClickHouse** — новые таблицы для сводного отчёта и результатов сверки
- **`webapp/app.py`** (веб-форма загрузки отчётов) — список кабинетов, новая
  форма загрузки
- **Metabase** — дашборд с результатами сверки

## Пользователь / выгодоприобретатель

- Пользователи: Илья + 3-5 сотрудников (в перспективе доступ может быть и у
  клиентов).
- Выгодоприобретатель: сама компания (более точная и глубокая аналитика по
  клиентам, база для дальнейших советов) и клиенты (более точные цифры).
- Метрика успеха: меньше времени на сборку крупных проектов, меньше ошибок,
  задел под дальнейшую автоматизацию площадок.
