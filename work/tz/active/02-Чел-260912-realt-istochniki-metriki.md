# Реальт — источники данных и метрики в Metabase

Техническая часть — см. [02-Тех-260912-realt-istochniki-metriki.md](02-Тех-260912-realt-istochniki-metriki.md).
Открывать по ходу реализации, не обязательно читать сразу целиком.
Термины (Проект, Кабинет и т.д.) — см. [глоссарий проекта](../../../docs/glossary.md).

## Задача

Нам нужно расширить `report.`-поддомен (webapp), чтобы у Реальта (второй
клиент платформы, психологическая клиника) **появилась** возможность
загружать свои данные — банковские выписки (1С), карточные выписки (PDF),
выгрузки из Клиентикс, выгрузки из Google-Таблиц (зарплаты, расходы по
статьям) — и **появилась** модель метрик в Metabase поверх этих данных, по
аналогии с тем, как это устроено для WB/Ozon.

Сейчас банковские/карточные выписки грузятся только вручную через CLI (нет
веб-формы), а Клиентикс и Google-Таблицы как источники данных вообще не
подключены. Без этой задачи данные Реальта не попадают в систему
самостоятельно — их придётся вручную гонять CLI-скриптами за клиента,
что не масштабируется на будущих клиентов.

## Условия результата

- [ ] На странице загрузки Реальта доступны формы: банковская выписка 1С,
      карточная выписка PDF, выгрузка Клиентикс, выгрузка Google-Таблицы
      «зарплаты», выгрузка Google-Таблицы «расходы по статьям»
- [ ] Каждая форма парсит файл и грузит данные в ClickHouse с привязкой к
      `project_id` Реальта
- [ ] Битый файл / разрыв сети до ClickHouse не роняет веб-форму — вместо
      этого понятная ошибка
- [ ] Код не хардкодит БД/project_id CloudSix или Реальта — заработает на
      БД Реальта, когда она будет готова (см. блокер в разделе
      «Исполнение»)
- [ ] Есть ClickHouse VIEW с формулами метрик Реальта (минимум — выручка
      по услугам; остальной состав метрик — на усмотрение Ильи, исходя из
      реально доступных данных)
- [ ] Поверх VIEW — Metabase Model, в папке коллекции Реальта, без
      дублирования формул в отдельных карточках
- [ ] Илья вручную сверяет логику расчёта метрик со своим черновиком
      дашбордов (черновик уже у него) и фиксирует результат сверки в
      самопроверке
- [ ] Ручной чек-лист проверки загрузки для каждого нового источника

## Каких систем может коснуться (ориентир, не обязательство)

Илья может решить задачу и без изменения части из них, если найдёт более
удачный путь:
- ClickHouse (новые таблицы/VIEW)
- `webapp/app.py` + шаблоны (новые роуты загрузки)
- Metabase (новая Model, коллекция Реальта, возможно дашборд)
- `scripts/create_user.py` (выдать доступ `user_projects` сотрудникам,
  которым вы откроете дашборды)

## Пользователь / выгодоприобретатель

Файлы загружает ваша команда (не сам Реальт). Выгодоприобретатель —
сотрудники Реальта, которым вы открываете доступ к дашбордам в Metabase.
Станет лучше то, что сейчас посчитать нельзя: выручка по услугам и в
перспективе более сложные показатели (LTV, юнит-экономика по врачам и
услугам) — для них важно, чтобы Клиентикс парсился на уровне отдельных
операций (пациент/врач/услуга/дата/сумма), а не только агрегатами, даже
если сами эти метрики не входят в объём этой задачи.
