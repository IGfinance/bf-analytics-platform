## Архитектура

Код уже в master (коммит на ветке `feat/realt-bank-cash-accruals`,
смержено `2026-09-17`). Ничего переписывать не нужно — только добавить
тесты поверх существующего:

- `src/realt_gsheets_core.py`:
  - `parse_bank_account(values) -> (rows, skipped)` — позиции колонок в
    `_BANK_POS`, строка — данные, если распознаётся `amount` (колонка 3)
  - `parse_cash(values) -> (rows, skipped)` — позиции в `_CASH_POS`
  - `parse_accruals(values) -> (rows, skipped)` — позиции в `_ACCRUALS_POS`,
    без полей «Проект»/«Мес» (в отличие от двух других)
  - общий каркас разбора строки — `_flat_row()`, используют все три
  - хелперы форматов: `_num()` (числа), `_date_slash()` (`ДД/ММ/ГГ`),
    `_accrual_date()` (`<день> <сокр.месяца>[.] <yy>`, включая узкий
    неразрывный пробел ` `)

Ориентир по структуре тестов — `tests/test_realt_expenses.py` (собрать
синтетический `values`, вызвать `parse_*`, проверить результат и
`skipped`), а не `tests/test_realt_payroll.py`, если там другой стиль —
смотреть по актуальному коду на момент работы.

**Важно:** существующие тесты для payroll/expenses не мокают
`ingest_*`/ClickHouse-клиент — тестируется только чистый слой
парсинга (`parse_*`). Держать тот же объём: `ingest_bank_account`/
`ingest_cash`/`ingest_accruals` тестами не покрывать (тянут Google
Sheets API + пишут в ClickHouse — не unit-тестируемо без моков, которых
в проекте пока нет ни для одного источника).

## Definition of Done (техническое)

      на позитивный кейс (строка с данными — все поля верны) и негативный

- [ ] Даты: `_date_slash` (`'05/01/26'` → `date(2026, 1, 5)`) и
      `_accrual_date` (`'5 янв. 26'` → `date(2026, 1, 5)`, включая случай
      с узким неразрывным пробелом `'22 авг. 25 '`)

      позиция во вкладке, как у остальных источников)
