# Детальный адаптер

Два дашборда Metabase (коллекция «CloudSix | Админка»): **04 … Детальный адаптер API** (id 20) и
**05 … Детальный адаптер xlsx** (id 21). Каждый — две плоские таблицы: WB и Ozon.

## Что внутри

Строка = кабинет × бренд × группа × статья, столбцы = месяцы выбранного года и «Итого». Фильтры дашборда:
Кабинет, Бренд, Год (по умолчанию 2026).

- Группы с номерами (`01 …`) входят в «К перечислению итого» и складываются в него.
- Группы «Справочно: …» (выручка и комиссия, количество, себестоимость, валовая прибыль, покрытие
  себестоимости, статьи вне итога) с ними не складываются — у них своя единица измерения или это та же
  сумма под другим углом.
- Статьи: Ozon xlsx — «группа услуг → тип начисления» отчёта; Ozon API — статьи cash-flow-statement с
  русскими названиями; WB — значения полей отчёта («Обоснование для оплаты», «Тип операции»).
- Бренд: WB — из отчёта, Ozon — из каталога API (`ozon_products`). Пустой бренд — название кабинета,
  CloudSix — «Cloud Six». Расходы Ozon уровня кабинета разложены по брендам пропорционально выручке
  бренда за месяц (оценка), привязанное к артикулу — точно.

## Где что лежит

## Сверка (проверено 2026-10-04)

«Итого» по группам начислений равно колонке «15 К перечислению» адаптерных карточек 43, 204, 203, 64
по каждой паре кабинет/бренд (расхождение ≤ 10⁻⁶). Для WB сумма статей каждой группы равна канонической
метрике бренд-вьюхи.

## Известные ограничения

- Скорость: при свободном сервере таблицы грузятся 4–7 с, при параллельной нагрузке — десятки секунд
  и таймауты. Задача на разбор — в вики («текущие приоритеты → Бэклог»).
- Названия статей cash-flow Ozon переведены по смыслу английских кодов; новый код без названия
  показывается как технический (тест `test_every_cashflow_item_has_russian_label`).
- Ozon xlsx заканчивается в середине июня — пока владелец не догрузит файлы.
