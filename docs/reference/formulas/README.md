# Формулы метрик — LaTeX

Один документ на проект (клиента) — единое место, где видно, как считается
каждая метрика на дашбордах Metabase, плюс ER-схема таблиц-источников.
Источник правды остаётся в коде (`src/schema_*.sql`,
`src/metabase_queries/*.sql`) — эти файлы описывают его человеческим
языком и не должны разойтись (см. последний раздел каждого документа).

- `realt.tex` — Реальт (клиника). Готово, собрано и проверено визуально.
- CloudSix (WB + Ozon) — следующим шагом, отдельный файл `cloudsix.tex`.

## Как собрать

Движок — **XeLaTeX** (не pdflatex — документ использует `fontspec` для
кириллицы через реальные Unicode-шрифты, а не старую связку
`babel`+`T2A`+`inputenc`):

```
xelatex realt.tex && xelatex realt.tex   # дважды — для оглавления
```

Или `latexmk -xelatex realt.tex`, или `tectonic realt.tex` (сам понимает,
сколько раз прогнать). Overleaf: в настройках проекта Compiler → XeLaTeX
(по умолчанию там обычно уже pdfLaTeX — переключить перед первой сборкой).

Шрифты — `\mainfont` "Times New Roman", `\monofont` "Courier New" (оба
протестированы на macOS: полный набор начертаний, есть кириллица). Если
на вашей машине/Overleaf таких имён нет — замените в начале `realt.tex`
на "Liberation Serif"/"Liberation Mono" или "TeX Gyre Termes"/"TeX Gyre
Cursor" (свободные, метрически близкие, обычно есть в любом TeX Live).
Проверяйте кириллицу в MONO-шрифте отдельно — у умолчательного (Latin
Modern Mono) её вообще нет, код вроде "ФОТ ШАА" печатает пустые
прямоугольники вместо букв вместо ошибки компиляции, легко пропустить.

## Как проверено

`realt.tex` собран локально (tectonic 0.17.0, движок XeTeX) и проверен
не только на «нет ошибок компиляции», но и визуально — все 11 страниц
постранично отрендерены в PNG и просмотрены, включая ER-диаграмму
(самую сложную по вёрстке часть) и все длинные SQL-идентификаторы в
таблицах/списках (они переносятся посимвольно через пакет `seqsplit` —
без него `realt_visits_categorized`-подобные имена без пробелов вылезали
за поля страницы, это была реальная, а не косметическая проблема).

При правке текста: если добавляете новый длинный
SQL/ClickHouse-идентификатор БЕЗ пробелов внутри (имя таблицы/колонки,
путь к файлу) — оборачивайте в `\texttt{\seqsplit{...}}`, не в `\code{}`
(тот использует `\detokenize`, который переносится только по границам,
уже вписанным в остальной текст, и не ломается только пока идентификатор
короткий). `\code{}` оставьте для фрагментов С пробелами внутри (условия
вида `amount > 0`) — `seqsplit` там, наоборот, съедает пробелы.
